# 项目引入数据库进行管理

**先使用SQLite数据库，完成个人任务管理系统。等到多人任务管理系统时，再转为PostgreSQL**

## 第一阶段任务

1. 了解数据库的优缺点，并且选择适合的数据库

2. 学习数据库的使用

3. 把当前项目的JSON格式转为数据库管理

4. 建立任务、附件、人员之间的关系型表，为之后关系型数据库PostreSQL建立基础

### 问题

1. 对数据库完全不了解，只能直接先了解优缺点，不了解不同数据库之间有什么区别和不同

- 数据库结构化保存数据(如任务表，团队表等)；方便后续查询，能加速查询；约束数据的正确性(数据是否能为空，附件必须依附于存在的任务等条件)，维护遵守的条件；维护事物的完整性，一组操作要么全部成功，要么全部失败；维护各种变量之间的关系

|类型|代表|适合做什么|
|---|---|---|
|嵌入式关系型数据库|SQLite|本地App,CLI,单机工具|
|服务端关系型数据库|PostgreSQL、MySQL|Web服务、多人在线、团队协作|
|文档数据库|MongoDB|JSON风格、结构变化大的数据|
|键值数据库/缓存|Redis、RocksDB|缓存、计数、临时状态|
|搜索引擎|Elasticserarch、OpenSearch|全文搜索、复杂搜索|
|对象存储/文件存储|本地附件目录、S3、MinlO|存PDF、Word、Excel等真实文件|

SQLite ：不需要启动服务器，程序直接打开一个 .db 文件。不需要安装数据库服务，数据库权限等问题<br>
优点：部署简单,有助于了解核心概念(表、主键、外键、SQL、事务、索引、参数绑定、数据迁移、错误处理、C++ RALL 资源管理)<br>
缺点：不适合多个远程用户直接共享同一个数据库文件；写并发有限；权限不是它的重点；


2. 对核心概念的理解：表、主键、外键、SQL、事务、索引、参数绑定、数据迁移、错误处理、C++ RALL 资源管理
